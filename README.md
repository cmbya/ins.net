# ins.net

本地运行的 Instagram 帖子与 Reels 归档器。手动添加需要归档的博主，公开内容可尝试不使用 Cookie；需要登录的内容可使用自己的 Instagram Cookie。

## 功能

- 手动维护监控博主，不读取或导入关注列表。
- 每位博主可选择同步帖子网格、Reels 或两者；每种已选内容均可设为最近 20 条或全部历史分批补齐。
- 每位博主单独选择扫描时“不使用 Cookie”或“使用 Cookie”；已有博主保持原选择，界面要求新博主明确选择。无 Cookie 扫描可能提前受限或漏掉历史页，不能据此保证全量完整。
- 下载始终先尝试公开方式，失败后只在账号已启用 Cookie 时重试一次。遇到 HTTP 429 会停止本轮下载，不继续使用 Cookie 请求；带 Cookie 扫描配置在授权关闭时临时改用公开扫描，并在日志中说明。
- 系统配置统一控制所有博主的自动同步间隔（最短 30 分钟）和每位博主的单轮下载上限（1–200 条）。两种内容同时启用时共用该上限，并轮换优先处理顺序，避免其中一种长期占满额度。
- 博主列表分别显示帖子网格、Reels 和合计归档作品数；Instagram 无法提供昵称或头像时显示用户名和默认头像。
- 同一账号按作品短码去重；同一 Reel 同时出现在帖子网格和 Reels 列表时只建一条作品记录、只下载一次。已完整归档作品会跳过且不占下载上限；跳过前会核对文件大小，每轮还会分批抽查旧归档，发现丢失或截断的媒体后自动补齐。轮播只下载缺失的媒体项。
- 数据看板提供作品总数、作者作品数、文件大小和每日同步曲线。双击作者可清除看板中的作品记录，数据库保留媒体路径以便核对磁盘；归档文件不会被删除。后续同步会跳过仍完整存在的文件，并重新下载已被手动删除或缺失的媒体。
- 同步记录提供发布时间、同步日期、账号、博主下拉列表、标题、来源、状态筛选和分页，可播放图片/视频、打开原帖、批量删除或恢复记录。
- 移出博主列表只停止监控，作品记录和文件仍保留；“删除作品记录”单独操作，两者均不会删除 NAS 文件。
- Instagram 授权页管理 Cookie 状态、账号备注、博主作品的保存目录，并可主动检查授权。
- 系统配置可设全局调度开关、所有博主统一间隔与上限、默认目录和日志保留天数。
- 系统日志可按日期、账号、级别、关键词和任务筛选，展示每次任务的汇总及逐条扫描/下载/跳过/失败信息；调度错误也会记入日志。可清除全部历史日志，或单独清除某条已结束任务及其详细日志；运行中的任务会保留。清理日志不会影响作品记录、Cookie 或归档文件。容器重启后，未结束任务会标记为“已中断”。Cookie 值会在采集器错误输出中遮盖。
- 帖子网格和 Reels 使用独立历史游标；轮播中的图片和视频按原媒体逐项保存。
- 可设置归档根目录下的子目录。归档根目录由 Compose 映射到 `/archive` 的 NAS 文件夹决定。
- 新下载作品按“发布日期+作品标题”创建文件夹，媒体文件按作品标题命名；轮播媒体在标题后加序号。作品标题沿用同步记录中显示的帖子正文；为满足文件系统规则会替换禁用字符并截短超长标题。已有完整归档留在原位置，部分归档继续在原位置修复。

## 飞牛桌面 Compose 部署（不用 SSH）

1. 在飞牛文件管理器确认归档文件夹 `/vol2/1000/docker/INS/insnet` 存在。Compose 会把它挂载到容器的 `/archive`。
2. 打开 **Docker → Compose → 新增项目**，选择创建 YAML，把 [compose.fnos.yaml](compose.fnos.yaml) 内容粘贴进去。
3. 修改 `INS_PASSWORD` 为至少 12 位的独立管理密码，并确认 `/vol2/1000/docker/INS/insnet:/archive` 左侧路径存在。
4. 默认归档写入身份为数字 UID/GID `10001:10001`。容器不会再修改 NAS 归档目录的属主或权限；若启动日志提示无法写入 `/archive`，请在该目录权限中授予此身份写入权限，或将 YAML 的 `INS_UID`、`INS_GID` 改成该目录所有者的数字 UID/GID。
5. 保存并构建、启动。使用飞牛自带的 `bridge` 网络，浏览器打开 `http://NAS_IP:18088`。
6. 更新已有项目时选择重新构建镜像并拉取 `main` 最新代码。只重启容器不会更新代码。保留 `insnet-data` 卷，它保存账号 Cookie、同步配置和归档记录。

容器构建需要网络访问 GitHub、PyPI 和 Debian 软件源。数据库与 Cookie 放在 Docker 命名卷 `insnet-data`；媒体文件写入 NAS 绑定目录。网页中的“保存子目录”是 `/archive` 下的相对路径，例如 `Instagram/备份`。如果主机端口 18088 被占用，可将 Compose 左侧端口换成其他空闲端口，例如 `18081:18080`。

## 命令行 Compose 部署

需要 Docker Compose、可访问 Instagram 的网络和足够的归档空间。

```sh
git clone https://github.com/cmbya/ins.net.git
cd ins.net
cp .env.example .env
# 编辑 .env 中的 INS_PASSWORD
mkdir -p data archive
docker compose up -d --build
```

浏览器打开 `http://NAS_IP:18080`。通过 HTTPS 反向代理访问时，在 Compose 环境中设置 `INS_COOKIE_SECURE=1`，登录 Cookie 将启用 Secure 属性。登录接口每个来源地址 15 分钟内最多允许 10 次失败尝试。管理密码和 Cookie 属于敏感凭据。数据库/Cookie 位于 `./data`，媒体位于 `./archive`，迁移前备份这两处目录。

## 使用

1. 登录后添加 Instagram 账号。只下载公开作品时可以不上传 Cookie；需要登录时，从自己的浏览器导出 **Netscape cookies.txt** 文件（含 `instagram.com` 的 `sessionid` 和 `csrftoken`）。Cookie 相当于登录凭据，不要分享或提交到 Git。
2. 在“博主列表”输入用户名添加，明确选择扫描作品时是否使用 Cookie，并勾选帖子网格、Reels 或两者。旧博主保持原选择；读取不到昵称或头像时显示用户名和默认头像。
3. 为每位博主选择“最新 20 条”或“全部历史”，此范围同时应用到该博主勾选的内容类型。同步间隔和每轮下载上限在系统配置中统一设置；两种内容同时启用时，本轮下载量按该博主合计。保存设置后可点“立即同步”。
4. “全部历史”每轮从最新页逐页扫描；完整归档的作品跳过，不占下载上限。公开扫描时，旧待处理作品需要再次扫描到媒体地址才能优先匿名下载，选择最新 20 条时更旧的待处理作品可切换全部历史处理。遇到 HTTP 429 会停止本轮请求并延长下次同步间隔。
5. 在 Instagram 授权页按账号设置 `/archive` 下博主作品的保存子目录；“允许使用 Cookie”开关关闭时，博主同步和定时调度仍运行，但扫描与下载都不会使用该账号的 Cookie。系统日志可查最近任务详情。公开访问也可能被 Instagram 限制，能否读取由 Instagram 当前提供的公开数据决定。

如果同步日志显示“读取 0 页 / Requested user could not be found”，失败发生在作品扫描阶段，媒体下载的 Cookie 回退尚未开始。这条上游错误也可能遮盖网络、授权或限流问题，不代表博主一定不存在。对曾成功同步的博主，如果本地保存有 Instagram 数字用户 ID，后续扫描会直接访问该用户的作品接口，跳过容易误报的用户名查询，并核对返回作品的用户名；仍失败时应看授权检测和安全诊断日志，不要连续点击立即同步。

“授权检测”先读取本地 Cookie 的 sessionid 过期时间；如果 Cookie 带有 ds_user_id，则直接用该数字 ID 请求账号的帖子接口，避开用户名资料查询。检测到过期会显示“Cookie 已过期”；接口拒绝、登录跳转或连接失败会显示“无法判定 Cookie”，不能据此认定 Cookie 失效。即使接口可访问，也不能单独证明 Cookie 有效，因为公开请求也可能成功。遇到持续登录跳转时应先停止反复同步，在浏览器检查账号能否正常访问，再核对 Cookie 导出时间和 NAS 网络。
